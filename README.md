# 스터디플래너

메가스터디 스터디플래너 양식을 본뜬 웹앱입니다. 서버 없이 열리는 정적 사이트(PWA)이고, 일정은 기기에 먼저 저장됩니다. 로그인하면 계정(Supabase)에도 저장되어 iPhone과 iPad가 같은 일정을 봅니다.

## 한눈에 보기

- 하루 한 페이지. 페이지마다 날짜, 시작 시각, 오늘의 목표, D-day, 할 일 목록, 복습 메모가 있습니다.
- 할 일마다 왼쪽에 색으로 구분되는 카테고리, 가운데에 내용, 오른쪽에 소요 시간·진행 시각·체크 칸이 있습니다.
- 소요 시간을 정하면 진행 시각이 앞 할 일이 끝난 시각부터 자동으로 이어집니다. (예: 앞 일이 PM 3:00에 끝나고 1시간 30분이면 PM 3:00 ~ 4:30)
- 오른쪽 시간표(10분 칸)에 계획한 시간이 카테고리 색으로 칠해지고, 아래에 계획·완료 시간 합계가 나옵니다.

## 파일

폴더 없이 한 단계에 모두 둡니다.

| 파일 | 역할 |
| --- | --- |
| `index.html` | 앱 전체 (화면, 스타일, 동작) |
| `config.js` | Supabase 주소와 공개 키. 비어 있으면 로그인 없이 이 기기에서만 동작 |
| `supabase.js` | Supabase 클라이언트 라이브러리 (supabase-js 2.x, 직접 포함) |
| `sw.js` | 서비스 워커. 오프라인 실행과 캐시 |
| `manifest.webmanifest` | 홈 화면에 추가할 때 쓰는 앱 정보 |
| `icon-192.png` `icon-512.png` `apple-touch-icon.png` | 앱 아이콘 |
| `setup-supabase.sql` | Supabase에 만들 테이블과 접근 규칙 |
| `README.md` | 이 문서 |

## 기능

### 할 일
- 카테고리: 칸 왼쪽을 눌러 고릅니다. 이름·색·"공부 시간에 포함"을 카테고리 관리에서 바꿉니다.
- 소요 시간: 시간 칸을 누르면 위아래로 끄는 알약 슬라이더가 열립니다. 5분 단위, +/- 버튼, 30분·1시간·1시간 30분·2시간 버튼이 있습니다. '취소'를 누르면 이번에 바꾼 시간을 버립니다.
- 체크 칸: 누를 때마다 없음 → 완료(✓) → 미뤄짐(→) → 취소(✕)로 바뀝니다.
- 할 일을 누르면 칸 아래에 작은 메뉴가 뜹니다. 스크롤해도 유지되고, 다른 곳을 탭하면 닫힙니다.
  - ↑ ↓: 그 할 일을 위나 아래로 옮깁니다.
  - 매일 / 매주: 반복 설정 (아래 참고).
  - 시간 자동: 직접 정한 시작 시각을 풀고 자동으로 이어붙입니다 (직접 정한 경우에만 보임).
  - 이 할 일 삭제: 삭제 후 몇 초 동안 "되돌리기"가 나옵니다.

### 진행 시각 규칙
- 기본은 자동입니다. 첫 할 일은 페이지의 시작 시각(기본 AM 6:00)에서 시작하고, 이후는 앞 할 일이 끝난 시각에 이어집니다.
- 시작 시각을 직접 고칠 수 있습니다. 고친 시각은 파란 실선 밑줄로 표시되고, 아래 할 일은 그 할 일의 끝 시각부터 이어져 밀립니다.
- 앞 일정이 끝나기 전에 시작하도록 고친 시각은 빨간색으로 겹침을 알려 줍니다.
- 아래쪽에 직접 고친 할 일이 따로 있으면 그 할 일은 고정된 시각에 그대로 있고, 밀리는 건 그 전까지입니다.
- 하루 시작보다 이른 시각이나 자정 이후의 시각은 다음 날 새벽으로 계산합니다.
- 순서를 ↑ ↓로 바꾸면 자리가 바뀐 두 할 일의 직접 정한 시각이 풀리고 자동으로 다시 이어집니다.
- 미뤄짐·취소 상태의 할 일은 시간을 차지하지 않습니다. 시각이 흐리게 보이고, 아래 할 일은 그 앞 일정이 끝난 시각에 바로 이어집니다. 시간표에도 칠해지지 않습니다.

### 페이지
- 처음 열면 오늘 날짜의 페이지가 열립니다. 없으면 이전 페이지의 시작 시각을 이어받아 새로 만듭니다.
- 날짜 선택(달력)으로 다른 날짜로 이동합니다. 일정이 있는 날은 달력에 표시됩니다.
- "이 페이지 복제"는 다음 날짜로 복제합니다. 그 날짜에 이미 페이지가 있으면 덮어쓸지 묻고, 덮어쓰면 기존 페이지는 완전히 삭제됩니다.
- "삭제"는 두 번 눌러야 삭제됩니다.
- 12시간제/24시간제 버튼으로 시각 표시를 바꿉니다.

### 반복
- 할 일 메뉴의 "매일"은 그 날짜 이후 모든 날의 같은 시각에, "매주"는 같은 요일 같은 시각에 그 할 일을 넣습니다.
- 미리 페이지를 만들어 두는 방식이 아니라, 해당 날짜의 페이지를 열 때 자동으로 채웁니다. 그래서 달력의 표시에는 아직 안 나타납니다.
- 켜진 버튼은 검은색으로 표시되고, 한 번 더 누르면 반복이 해제됩니다. 이미 들어간 할 일은 남습니다.
- 반복으로 들어온 할 일을 그날만 지우면 그 날짜에는 다시 생기지 않습니다.
- 반복으로 들어간 할 일은 시각이 고정됩니다.

### 백업
화면 맨 아래의 백업 저장·불러오기로 JSON 파일을 내보내고 가져옵니다. 가져오기는 기존 일정에 합칩니다.

## 설치와 배포

### 1단계: GitHub Pages에 올려서 쓰기 (로그인 없이)
1. GitHub에서 새 저장소(Public)를 만들고 위 파일을 모두 올립니다. 폴더를 만들면 안 됩니다. (폴더째 올리면 파일이 한 단계로 펴집니다.)
2. Settings > Pages에서 main 브랜치, `/ (root)`로 저장합니다.
3. 나온 주소를 iPhone Safari로 열고 공유 버튼 > "홈 화면에 추가"를 누릅니다.

이 단계에서는 `config.js`가 비어 있어서 로그인 화면이 없고, 일정은 그 기기에만 저장됩니다.

### 2단계: 계정 동기화 켜기 (Supabase)
1. supabase.com에 가입하고 New project를 만듭니다 (Free 플랜, 지역은 Seoul이 가깝습니다). 데이터베이스 비밀번호는 따로 적어 두세요.
2. SQL Editor > New query에 `setup-supabase.sql`의 내용을 붙여 넣고 Run을 누릅니다. 자기 일정은 자기만 볼 수 있게 하는 규칙까지 들어 있습니다.
3. Authentication > Sign In / Providers > Email에서 "Confirm email"을 끕니다. 켜 두면 가입 때 확인 메일이 필요한데, 기본 메일 발송은 제한이 큽니다.
4. Project Settings > API에서 Project URL과 anon(또는 publishable) 키를 복사합니다.
5. GitHub에서 `config.js`를 열어 두 값을 따옴표 안에 붙여 넣고 Commit changes를 누릅니다.
6. 1~2분 뒤 앱을 열면 로그인 창이 먼저 나옵니다. "처음이에요 · 회원가입"으로 가입합니다. 아이디는 이메일 형식입니다.
7. 다른 기기에서도 같은 주소를 열고 같은 아이디로 로그인하면 일정이 내려옵니다.

anon 키는 화면에 노출되어도 되는 키이고, SQL의 규칙이 계정마다 데이터를 분리합니다. 비밀 키(service_role)는 절대 넣지 마세요.

### 3단계: 비밀번호 재설정 켜기 (선택)
앱에는 로그인 화면의 "비밀번호를 잊었어요" → 메일의 링크 → 새 비밀번호 입력 흐름이 들어 있습니다. 동작하려면 Supabase에서 다음을 해야 합니다.
1. Authentication > URL Configuration의 Site URL과 Redirect URLs에 앱 주소(`https://아이디.github.io/저장소/`)를 넣습니다.
2. 메일이 실제로 도착하게 하려면 Authentication > Emails > SMTP Settings에 외부 메일 서비스(Resend, Brevo, SendGrid 등)를 연결합니다. Supabase 기본 발송은 하루 발송량이 매우 적고 프로젝트 팀원에게만 갈 수 있습니다. 서비스별 무료 구간과 발신 주소 인증 조건은 각 사이트에서 확인하세요.
3. 메일 문구는 Authentication > Emails에서 한국어로 바꿀 수 있습니다.

존재하지 않는 이메일로 가입한 계정은 메일을 받을 수 없어 복구할 수 없습니다.

## 동기화 규칙

- 페이지마다 마지막에 고친 기기의 내용이 이깁니다. 같은 페이지를 두 기기에서 동시에 고치면 나중에 고친 쪽만 남습니다.
- 오프라인에서도 쓸 수 있고, 연결되면 알아서 맞춰집니다. 고친 뒤 1.5초 뒤, 앱이 열려 있으면 1분마다, 다시 열 때마다 확인합니다.
- 삭제는 "삭제 표시"를 남겨서 다른 기기에서 되살아나지 않게 합니다.
- 로그아웃하면 그 기기의 일정은 지워지고(계정에는 남아 있습니다), 다른 계정의 일정이 섞이지 않게 합니다.
- "로그인 없이 이 기기에서만 쓰기"를 누르면 로그인 없이 쓸 수 있고, 나중에 화면 맨 아래의 "로그인"으로 합칠 수 있습니다.

## 저장되는 데이터

- 기기: 브라우저 localStorage (`studyplanner.v1`, `studyplanner.owner`, `studyplanner.localmode`).
- 계정: Supabase 테이블 `planner_docs(user_id, doc_id, data, deleted, updated_at)`. `doc_id`가 `meta`이면 카테고리·페이지 순서·반복 규칙·삭제 표시, `p-<페이지 id>`이면 하루치 페이지입니다.
- 관리자(프로젝트 주인)는 Supabase 대시보드에서 가입한 이메일과 모든 사용자의 데이터를 볼 수 있습니다. 비밀번호는 암호화되어 있어 볼 수 없습니다. 다른 사람에게 공유한다면 이 점을 알려 주세요.

## 업데이트하는 방법

1. 바뀐 파일을 GitHub에서 같은 이름으로 덮어씁니다.
2. `index.html` 외의 파일을 바꿨다면 `sw.js` 맨 위의 `CACHE = 'studyplanner-vN'`의 숫자를 올립니다. (그래야 기기에 새 버전이 반영됩니다. `index.html`은 열 때마다 새 버전을 먼저 확인합니다.)
3. 홈 화면의 앱을 완전히 닫았다가 다시 엽니다.

## 알아둘 점

- 무료 플랜의 Supabase 프로젝트는 일주일 동안 사용이 거의 없으면 일시 정지됩니다. 대시보드에서 Resume project를 누르면 데이터 그대로 돌아오고, 정지된 프로젝트는 1년 동안 복구할 수 있다고 Supabase 문서에 나와 있습니다. 무료 조건은 바뀔 수 있으니 정확한 내용은 Supabase 요금 페이지에서 확인하세요.
- 글꼴(Noto Sans KR, IBM Plex Mono)은 처음 열 때 인터넷에서 받아 보관합니다.
- 앱은 기기에도 저장하는 구조라서, Supabase가 멈춰도 쓰던 기기에서는 계속 쓸 수 있습니다. 가끔 백업을 내려받아 두세요.
- 지금까지의 시험은 가짜 서버를 이용한 동작 확인이고, 실제 Supabase와의 동기화·메일 발송은 직접 확인해야 합니다.
